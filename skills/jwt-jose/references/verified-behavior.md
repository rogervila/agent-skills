## RFC Test Vectors

`assets/test-vectors.json` was generated by extracting tokens and keys from the RFC texts with a script, not by hand. Extraction was validated by recomputing the HMAC of RFC 7515 A.1 and RFC 7520 4.4 with their published keys, and by reproducing the RFC 7638 and RFC 8037 A.3 thumbprints. `scripts/jose_inspect.py` reports no error findings for any of the 23 compact RFC 7515, 7516, and 7520 vectors or the 4 JSON Serialization examples from RFC 7515 A.6-A.7 and RFC 7516 A.4-A.5. Evidence: Run.

An independent review on 2026-11-12 found inspector edge cases (unhashable JWK values, non-finite numbers, deep nesting, non-UTF-8 files, unchecked JSON-serialized headers, RFC 7797 compact payloads, detached JSON payloads, `--` in thumbprint `kid` values). Each is fixed and covered by `ReviewRegressions` in `scripts/test_jose_inspect.py`. Evidence: Run.

## jose 6.2.17 (JavaScript)

| Behavior | Result | Evidence |
|---|---|---|
| `jwtVerify` with `algorithms`, `issuer`, `audience`, `typ`, `requiredClaims` | Rejects wrong `aud`, wrong `iss`, wrong `typ`, missing `exp`, expired beyond `clockTolerance`, unknown `kid`, tampered payload. | Run |
| `typ` matching | `typ: "at+jwt"` accepts `at+jwt`, `application/at+jwt`, and `AT+JWT`; rejects `JWT`. | Run, Source (`normalizeTyp`) |
| Missing `exp` | Accepted unless `requiredClaims` includes `exp`. | Run |
| `alg: none` | Never accepted by `jwtVerify`, with a key or a JWKS. | Run |
| Algorithm confusion (HS256 MACed with an RSA public key) | Rejected: key type mismatch, or `ERR_JOSE_ALG_NOT_ALLOWED` with an allowlist. | Run |
| JWS JSON serialization or JWE passed to `jwtVerify` | Rejected: `Invalid Compact JWS`. | Run |
| HMAC secret length | No minimum enforced; a 19-byte HS256 secret signs and verifies. | Run |
| `generateKeyPair` | Keys are non-extractable unless `{ extractable: true }`. | Run |
| `createRemoteJWKSet` defaults | `cacheMaxAge` 600000 ms, `cooldownDuration` 30000 ms, `timeoutDuration` 5000 ms; exactly one key must match. Cached across verifications in the example (one fetch). | Source, Run |
| Decryption defaults | PBES2 refused unless listed; `maxPBES2Count` 10000; `maxDecompressedLength` 250000 bytes. | Source |
| JWE segment sizes | RSA-OAEP-256 with RSA-2048: encrypted key 256 bytes; A256GCM IV 12 bytes and tag 16 bytes; `dir` and `ECDH-ES` produce an empty encrypted key segment; ECDH-ES adds `epk`. | Run |
| Nested JWT example | `openNestedToken` rejects missing `cty`, an `enc` outside the allowlist, and an unsigned inner token. | Run |

## joserfc 1.8.0 (Python)

| Behavior | Result | Evidence |
|---|---|---|
| `jwt.decode` default | Verifies a JWS; a JWE raises `DecodeError` unless a `JWERegistry` is passed. | Run, Source |
| `alg: none` | Rejected ("not recommended" by default, "not allowed" with an allowlist). | Run |
| Claims | Not validated by `decode`; `JWTClaimsRegistry(...).validate()` checks `iss`, `aud`, `exp`, essentials, with `leeway`. | Run, Source |
| `jwk.thumbprint(dict)` | Hashes every member passed. The full RFC 7638 example JWK (with `alg` and `kid`) gives `w9MLyJXZRDnOemuK9wkP_1NRLP0sr9PAUMJhB_MSZrE`, not the RFC value `NzbLsXh8uDCcd-6MNwXF4W_7noWXFZAfHkxZsRGC9Xs`. `RSAKey.import_key(jwk).thumbprint()` and passing only `e`, `kty`, `n` give the RFC value. | Run, Source |
| Nested example | Rejects wrong `aud`, unknown signing key, unsigned inner token, missing `cty`, `enc` outside the allowlist. | Run |
